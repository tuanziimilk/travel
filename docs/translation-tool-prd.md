# 多语种混合文件翻译工具 PRD

## 1. 文档信息
- 产品名称：多语种混合文件翻译工具
- 文档类型：正式立项评审版 PRD
- 适用对象：产品、研发、业务
- 当前版本：V1.0
- 文档日期：2026-03-27

## 2. 产品背景
当前业务覆盖多个国家和语言市场，运营同学日常会处理大量跨市场内容。实际工作中，单个 `CSV/XLSX` 文件内经常同时存在多种语种内容，且不同列、不同记录、甚至同一个单元格内都可能混合多种语言。

当前 OP 主要通过 Google 翻译网页处理这类内容，但现有方式存在以下问题：
- 同一文件内多语种混合内容无法被顺畅统一处理
- 需要人工先拆分语言，再分别翻译，操作繁琐
- 容易出现漏翻、错翻、重复翻译和版本不一致
- 批量处理效率低，人工成本高
- 处理结果缺少任务追踪和结果沉淀，复盘困难

因此，需要在现有内部工具中新增一个独立的翻译工具工作区，支持同文件多语种内容的统一上传、统一识别、统一翻译为简体中文，并输出可下载结果。

## 3. 问题定义
### 3.1 当前核心问题
1. 单文件内多语种混合内容处理成本高
2. 翻译流程过度依赖人工拆分和人工判断
3. 结果缺乏统一入口、统一格式和统一回收方式
4. 运营处理效率低，且准确性高度依赖个人经验

### 3.2 本次产品要解决的问题
1. 让用户无需人工拆分语言，即可对混合语种内容发起统一翻译
2. 提供文本即时翻译和文件批量翻译两种模式，覆盖轻量与批量场景
3. 提供任务状态、识别摘要和结果下载能力，提升可追踪性
4. 将目标语言统一为简体中文，降低产品首期范围复杂度

## 4. 产品目标与非目标
### 4.1 产品目标
- 支持同文件多语种内容统一上传与批量翻译
- 支持用户输入任意语言或混合语种文本并即时翻译为简体中文
- 支持用户手动选择待翻译列，减少无效翻译和误翻
- 支持返回识别摘要，帮助用户理解翻译结果来源
- 支持最近任务查看与结果下载，提升任务可追踪性
- 降低人工拆分语言和重复操作成本

### 4.2 非目标
- 首期不支持 `docx/pdf/图片 OCR` 等复杂文档输入
- 首期不支持完整历史中心、复杂筛选和长期归档
- 首期不支持用户自定义结果列命名规则
- 首期不在产品层锁定具体翻译服务商
- 首期不承诺支持富文本样式、合并单元格等高级格式保留

## 5. 用户角色与核心使用场景
### 5.1 用户角色
- OP / 运营同学：主要使用者，负责实际翻译处理
- 产品经理：关注能力边界、使用成本、上线价值
- 研发：关注输入输出规则、任务处理逻辑、服务商可替换性

### 5.2 核心使用场景
#### 场景 A：文本即时翻译
用户手头有一段混合语种文本，需要快速翻译为简体中文并立即复制使用。

#### 场景 B：批量文件翻译
用户收到一个 `CSV/XLSX` 文件，其中不同列、不同记录存在多种语言，需要统一翻译为简体中文并导出结果文件。

#### 场景 C：任务回看与下载
用户需要查看最近执行过的翻译任务状态，并重新下载结果文件供后续使用。

## 6. 功能需求
## 6.1 翻译工具入口
- 在现有工具侧边栏新增独立工作区：`翻译工具`
- 工作区下包含两个页面：
  - `批量翻译`
  - `文本翻译`

## 6.2 文本翻译
### 功能说明
- 用户输入任意语言或混合语种文本
- 系统将文本统一翻译为简体中文
- 页面展示翻译结果与识别摘要

### 页面要素
- 目标语言区域
  - 首期固定输出为简体中文
  - 页面可展示“目标语言：简体中文”，无需用户反复选择
- 原文输入区
  - 支持多段文本输入
  - 展示字符计数
- 主操作区
  - 开始翻译
  - 清空输入
- 结果区
  - 展示翻译结果
  - 支持复制结果
  - 支持将结果回填到输入框继续处理
- 识别摘要区
  - 检测语言
  - 是否混合语种
  - 预计费用（若系统提供）

### 行为规则
- 输入为空时不可提交
- 文本长度超过上限时，提示改用批量翻译
- 翻译完成后保留结果，便于复制和继续处理

## 6.3 批量翻译
### 功能说明
- 用户上传 `CSV/XLSX`
- 系统解析首个 sheet/表头
- 用户手动选择需要翻译的列
- 系统将选中列统一翻译为简体中文
- 结果文件保留原列，并新增翻译结果列

### 页面要素
- 上传文件区
  - 支持 `.csv` 和 `.xlsx`
  - 展示文件大小和行数限制提示
- 当前文件卡片
  - 文件名
  - 总行数
  - 可选列数
- 待翻译列选择区
  - 展示列名
  - 展示示例值
  - 支持“全选文本列”
  - 支持“清空选择”
- 高级设置
  - 上传人
  - 任务备注
- 主操作区
  - 开始批量翻译
  - 显示本次任务摘要

### 行为规则
- 上传后先解析文件，再允许用户选择列
- 至少选择一列才能提交翻译
- 文件为空、格式不支持、行数超限时需明确提示
- 翻译为异步任务，不阻塞页面
- 结果文件保留原列，并新增：
  - `<原列名>__translated`
  - `<原列名>__detected_langs_summary`

## 6.4 当前任务反馈
- 展示当前任务状态：
  - 排队中
  - 处理中
  - 已完成
  - 部分失败
- 展示当前任务进度：
  - 已处理行数 / 总行数
  - 成功行数
  - 失败行数
  - 混合语种行数
- 展示识别摘要：
  - 检测到的语言种类
- 当前任务完成后可直接下载结果

## 6.5 最近任务
- 仅保留最近任务，不做完整历史中心
- 列表至少展示：
  - 任务 ID
  - 状态
  - 目标语言
  - 处理摘要
  - 开始时间
  - 下载按钮
- 用户可重新下载历史结果文件

## 7. 业务规则与边界条件
### 7.1 输入规则
- 首期支持文件类型：`CSV/XLSX`
- 首期不支持：`docx/pdf/图片 OCR`
- 待翻译源语言不设固定范围
- 同一文件、同一列、同一单元格可存在混合语种

### 7.2 翻译规则
- 首期目标语言固定为：**简体中文**
- 用户手动选择翻译列，不做自动猜列
- 以字段级文本为处理单元
- 单元格翻译失败不影响整批任务结束
- 允许批量任务部分成功、部分失败

### 7.3 结果规则
- 输出文件保留原列
- 新增翻译列与语言摘要列
- 支持下载结果文件
- 当前任务及最近任务均可触发结果下载

### 7.4 存储与追踪
- 仅保留最近任务记录
- 首期不做长期历史归档、复杂检索和统计分析

## 8. 交互与页面方案
### 8.1 翻译工具入口
- 左侧侧边栏独立入口：翻译工具

### 8.2 文本翻译页
- 顶部展示页面标题和一句操作说明
- 中部采用左输入、右结果布局
- 输入区优先级高于结果区
- 未翻译前，结果区展示轻量占位，不展示空白重编辑器
- 结果出来后才突出复制和回填动作

### 8.3 批量翻译页
- 按步骤组织流程：
  1. 上传文件
  2. 选择待翻译列
  3. 设置任务信息
  4. 开始翻译
- 当前文件卡片固定展示，避免用户来回滚动确认
- 当前任务结果在页面内可直接下载
- 最近任务列表作为次级信息，不抢占主流程

## 9. 成本与服务商策略
### 9.1 目标
在满足翻译质量和业务可用性的前提下，控制批量翻译的调用成本，并保留后续替换供应商的空间。

### 9.2 产品层原则
- 翻译引擎可插拔
- 产品层不锁定具体服务商
- 服务商方案在技术评估阶段定版
- 需优先平衡成本、效果和接入复杂度

### 9.3 服务商比选维度
- 单价 / 批量价格
- 混合语种处理效果
- 语言检测能力
- 文件 / 批量处理能力
- API 接入复杂度
- 稳定性
- 结果一致性
- 供应商替换成本

### 9.4 待评估服务商矩阵
| 方案类型 | 说明 | 适配方向 |
|---|---|---|
| 专用翻译 API | 传统翻译服务，偏稳定与标准化 | 适合成本和稳定性优先场景 |
| 通用 LLM API | 兼顾理解和混合语种处理 | 适合复杂文本和混合语种场景 |
| 双引擎混合方案 | 低成本主通道 + 高质量兜底 | 适合中长期成本与效果平衡 |

### 9.5 当前建议写法
- PRD 层仅定义可插拔要求
- 技术方案阶段再确定主供应商、兜底供应商与切换策略
- 立项评审时需同步评估成本与效果平衡

## 10. 数据与结果输出
### 10.1 文本翻译输出
- 翻译结果文本
- 语言识别摘要

### 10.2 批量翻译输出
- 原文件内容
- 翻译结果列
- 语言摘要列
- 任务状态
- 任务摘要

### 10.3 结果文件命名
- 按任务生成结果文件名
- 支持重复下载

## 11. 验收标准与指标
### 11.1 功能验收
#### 文本翻译
- 输入单语种文本可返回简体中文结果
- 输入混合语种文本可返回统一简体中文结果
- 返回语言识别摘要
- 超长文本提示切换到批量翻译

#### 批量翻译
- 支持 CSV/XLSX 上传
- 支持表头解析与翻译列选择
- 支持统一翻译为简体中文
- 输出文件保留原列并新增翻译结果列
- 支持任务状态查看和结果下载

### 11.2 业务可用性验收
- 翻译覆盖完整，无明显漏行漏列
- 混合语种内容可被统一处理
- 用户可在不拆分语言的前提下完成主要翻译任务

### 11.3 产品成功指标（建议）
- OP 单次翻译处理耗时下降
- 人工拆分语言操作显著减少
- 批量翻译任务完成率提升
- 结果下载与复用率提升

## 12. 风险与后续规划
### 12.1 主要风险
- 不同服务商对混合语种效果差异较大
- 批量翻译成本在高频使用下可能快速上升
- 小语种与营销文案的质量稳定性存在不确定性
- 用户对“语言识别摘要”的理解可能存在偏差

### 12.2 后续规划
- 评估并确定主翻译引擎与兜底策略
- 支持更多目标语言
- 补充长期任务历史与筛选能力
- 评估更复杂文件类型支持
- 增加术语表 / glossary / 固定翻译策略能力

## 13. 附录：首期范围结论
- 产品名称：多语种混合文件翻译工具
- 首期目标语言：简体中文
- 源语言范围：不固定
- 输入模式：文本翻译 + 批量翻译
- 文件类型：CSV/XLSX
- 服务商策略：可插拔，不锁定具体供应商
- 成本策略：作为正式立项评审中的独立章节进行评估
