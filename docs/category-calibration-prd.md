# Category 校准工具 PRD

## 1. 文档信息
- 产品名称：Category 校准工具
- 文档类型：正式 PRD
- 适用对象：产品、研发、运营
- 当前版本：V1.0
- 文档日期：2026-04-09

## 2. 产品背景
当前业务数据中已经存在 `当前-category id` 和 `当前-categoryName` 字段，但实际归类结果存在误判，导致商家分类不稳定、下游使用口径不一致。运营团队目前主要依赖人工结合 `Meta` 与 `About` 内容逐条判断分类是否正确，再手动给出建议分类。

现有流程存在以下问题：
- 人工逐条判断成本高，批量处理效率低
- 不同人员的判断标准不完全一致，口径不稳定
- 缺少标准化的任务入口、队列和历史结果下载能力
- 当前工具侧边栏中没有独立的 category 校准工作区

因此，需要在现有工具中新增独立的 `Category 校准工具`，支持批量上传待校准数据、基于内置分类字典和 AI 自动完成 category 判断，并输出可下载结果。

## 3. 问题定义
### 3.1 当前核心问题
1. 现有 category 结果存在误分类，但缺少高效校准工具
2. 依赖人工阅读 `Meta + About` 进行判断，耗时高且一致性不足
3. 缺少标准化任务队列与历史结果回看能力

### 3.2 本次产品要解决的问题
1. 为运营提供批量 category 校准入口
2. 通过 AI 结合分类字典自动判断“当前分类是否正确”
3. 输出标准化结果文件，便于复核与下游使用
4. 支持最近任务查看与结果下载

## 4. 产品目标与非目标
### 4.1 产品目标
- 支持上传待校准 `.xlsx` 文件并进行预览校验
- 支持基于内置分类字典和 AI 自动判断当前分类是否正确
- 支持输出建议父类和建议子类
- 支持创建异步任务、查看队列状态、下载结果文件
- 支持查看最近两周任务历史

### 4.2 非目标
- 首版不支持用户上传分类字典
- 首版不支持 `.csv`、`.json`、`.jsonl` 等额外输入格式
- 首版不输出“判断理由”列
- 首版不做复杂历史筛选、人工复核页、批量回写功能

## 5. 用户角色与核心场景
### 5.1 用户角色
- 运营 / OP：上传待校准文件、发起任务、下载结果
- 负责人 / 复核人：查看最近任务并复核结果

### 5.2 核心使用场景
#### 场景 A：批量 category 校准
用户上传包含商家信息与当前 category 的 Excel 文件，系统自动判断每条记录当前分类是否正确，并给出建议父类和建议子类。

#### 场景 B：任务回看与结果下载
用户需要查看最近执行过的 category 校准任务，了解处理状态，并重新下载历史结果文件。

## 6. 功能需求
### 6.1 侧边栏入口
- 在现有工具侧边栏“其他工具”分组下新增独立入口：`Category 校准工具`
- 与 `GG采集数据清洗工具` 同层级展示

### 6.2 页面结构
页面分为三个区域：
1. 上传文件
2. 任务信息
3. 最近任务

### 6.3 上传文件
#### 功能说明
- 用户上传 `.xlsx` 文件
- 系统校验文件格式、必填列和有效行数
- 上传成功后展示预览摘要

#### 必填列
- `TermID`
- `TermName`
- `Domain`
- `Landing Page`
- `Country`
- `Language`
- `Meta`
- `About`
- `当前-category id`
- `当前-categoryName`

#### 页面反馈
- 展示当前文件名
- 展示总行数和有效行数
- 若缺失任一必填列，则明确报错

### 6.4 任务信息
#### 功能说明
- 用户选择 `上传人`
- 用户填写任务备注
- 点击按钮创建 category 校准任务

#### 行为规则
- 创建任务前必须完成文件上传与预览
- 任务进入单任务串行队列
- 创建任务后页面给出任务 ID 与创建成功提示

### 6.5 最近任务
#### 功能说明
- 展示最近两周的任务记录
- 支持刷新列表
- 支持查看状态、处理摘要、开始时间、耗时
- 已完成任务支持下载结果

#### 最低展示字段
- 上传人
- 任务 ID
- 状态
- 处理摘要
- 开始时间
- 耗时
- 下载按钮

## 7. 输入输出定义
### 7.1 输入文件
- 首版仅支持 `.xlsx`
- 使用当前 demo 模板结构
- 分类字典由系统固定读取，不允许用户上传

### 7.2 分类字典
系统固定读取本地分类字典文件：

`D:\工作文件\临时任务\category判断相关附件\分类信息.xlsx`

字典结构包含：
- `分类ID`
- `分类等级`
- `分类名称`
- `父级分类ID`
- `父级分类名称`

其中：
- 一级分类作为建议父类候选
- 二级分类作为建议子类候选
- 建议子类必须属于对应建议父类

### 7.3 输出结果
结果文件仅输出以下 5 列：

| 列名 | 说明 |
|---|---|
| `domain` | 商家域名 |
| `当前分类` | 当前分类展示值，格式为 `id · name` |
| `判断` | `正确` 或 `有误` |
| `建议父类` | 建议父类展示值，格式为 `id · name` |
| `建议子类` | 建议子类展示值，格式为 `id · name` |

### 7.4 输出范围
- 输出包含全部记录，不只保留错误项
- 对于判断为 `正确` 的记录，也保留建议父类和建议子类，便于筛选和复核

## 8. 判断逻辑与业务规则
### 8.1 AI 输入信息
每条记录至少使用以下字段进行判断：
- `TermName`
- `Domain`
- `Country`
- `Meta`
- `About`
- `当前-category id`
- `当前-categoryName`
- 分类字典中的父子类信息

### 8.2 AI 输出要求
AI 需要返回结构化结果：
- 当前分类判断结果
- 建议父类 ID / 名称
- 建议子类 ID / 名称

### 8.3 结果约束
- 建议父类必须是一级分类
- 建议子类必须存在于字典中
- 建议子类必须属于对应建议父类
- 若 AI 返回非法分类组合，则视为无效结果并重试

### 8.4 判断值
- `正确`
- `有误`

### 8.5 正确记录的处理规则
- 对于 AI 判断为 `正确` 的记录，结果文件仍输出建议父类和建议子类
- 若当前分类能映射到合法父子类，则结果文件回填该合法父子类

## 9. 页面与交互方案
### 9.1 整体风格
- 视觉和交互风格与 `GG采集数据清洗工具` 保持一致
- 复用上传卡片、任务卡片、队列表格、下载按钮等现有交互模式

### 9.2 任务状态
至少包含以下状态：
- `queued`
- `running`
- `done`
- `failed`

### 9.3 下载规则
- 仅完成任务可下载结果
- 下载文件格式为 `.xlsx`

- 在前端新增独立页面 `CategoryCalibrationPage`
- 在侧边栏新增 `/category-calibration` 路由入口

## 11. 验收标准
### 11.1 功能验收
- 合法 `.xlsx` 文件可成功上传与预览
- 缺失任一必填列时会明确报错
- 任务可创建并进入队列
- 任务完成后可下载结果文件
- 结果文件仅包含固定 5 列，且列顺序正确
- 建议父类与建议子类必须来自合法分类字典关系
- 最近任务列表可查看最近两周记录并支持下载

### 11.2 回归验收
- `GG采集数据清洗工具` 原有功能不受影响
- “其他工具”下两个入口均可正常访问

## 12. 风险与后续规划
### 12.1 风险
- AI 对边界类目判断可能存在波动
- 分类字典更新依赖本地文件维护
- 当前分类与目标父子类结构不完全一致时，需要额外兜底逻辑

### 12.2 后续规划
- 支持 `CSV` 上传
- 支持输出“判断理由”列
- 支持人工复核页
- 支持分类字典配置化或后台维护
